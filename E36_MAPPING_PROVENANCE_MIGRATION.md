# DeepAuditCrossWalk — E3.6 Mapping Provenance Migration Report

## Executive Summary

Prior to E3.6, DeepAuditCrossWalk inferred mapping authority and provenance via fragile string heuristics in `_is_auto_extracted_mapping_rationale()`. If a mapping's human-authored rationale happened to begin with phrases like `"Clause contains facet '"`, it could be downgraded to auto-extracted, or vice-versa: an analyst editing text could inadvertently alter provenance detection.

E3.6 replaces this heuristic with explicit, first-class structured metadata: `mapping_origin: MappingOrigin`.

---

## 1. Provenance Architecture vs. Review Approval

A critical architectural distinction is enforced between **Mapping Origin** and **Review Status**:

```
+---------------------------------------------------------------------------------+
|                               ClauseControlMapping                              |
+----------------------------------------------------+----------------------------+
| Provenance / Authorship (mapping_origin)            | Governance (review_status) |
| - AUTO_EXTRACTED: generated by ingestion engine    | - PROPOSED                 |
| - HUMAN_AUTHORED: created/authored by human expert | - APPROVED                 |
| - IMPORTED: bulk imported from external taxonomy   | - CONFIRMED                |
| - LEGACY_UNKNOWN: pre-E3.6 historical record       | - REJECTED                 |
+----------------------------------------------------+----------------------------+
```

### Key Invariants
1. **Rationale Invariance**: Modifying a mapping's `rationale` string (free-form text) **never** changes its `mapping_origin` or its `review_status`.
2. **Authority Decoupling**: A mapping is considered human-authored if and only if `is_human_authored_mapping(m)` returns `True`, based on `m.mapping_origin == MappingOrigin.HUMAN_AUTHORED`.
3. **Approval Boundary**: Even human-authored mappings must progress through the review workflow (`APPROVED`/`CONFIRMED`) before they can establish confirmed crosswalk coverage.
4. **Imported Untrusted Boundary**: Mappings with origin `IMPORTED` are treated with the same conservative scrutiny as auto-extracted candidates until formally approved.

## 2. Model & API Schema Updates

### 2.1 Model Definition (`backend/banking_crosswalk/models.py`)

```python
class MappingOrigin(str, Enum):
    AUTO_EXTRACTED = "auto_extracted"
    HUMAN_AUTHORED = "human_authored"
    IMPORTED = "imported"
    LEGACY_UNKNOWN = "legacy_unknown"

class ClauseControlMapping(BaseModel):
    ...
    mapping_origin: MappingOrigin = Field(default=MappingOrigin.LEGACY_UNKNOWN)

    @field_validator("mapping_origin", mode="before")
    @classmethod
    def _validate_mapping_origin(cls, v: Any) -> Any:
        if v is None or v == "":
            return MappingOrigin.LEGACY_UNKNOWN
        if isinstance(v, str):
            try:
                return MappingOrigin(v)
            except ValueError:
                return MappingOrigin.LEGACY_UNKNOWN
        return v
```

### 2.2 Storage & Review Endpoints (`backend/banking_crosswalk/api.py`, `store.py`)

- `ClauseMappingReviewRequest` includes optional `mapping_origin: Optional[MappingOrigin] = None`.
- `TenantStore.update_clause_mapping_review()` accepts `mapping_origin` parameter, strictly bounded by tenant isolation (`tenant_id`).
- Automated policy extraction (`policy.py:extract_enterprise_policy`) explicitly tags extracted mappings with `MappingOrigin.AUTO_EXTRACTED`.

## 3. Backward Compatibility & Migration Strategy

### 3.1 Legacy Serialization Safety
- Pre-existing stored JSON payloads (in SQLite, PostgreSQL JSONB, or serialized session baselines) that do not contain `mapping_origin` deserialize cleanly to `MappingOrigin.LEGACY_UNKNOWN`.
- Payloads passing `null` or empty string are safely coerced to `MappingOrigin.LEGACY_UNKNOWN`.

### 3.2 Legacy Fallback Logic (`is_human_authored_mapping`)
```python
def is_human_authored_mapping(m: ClauseControlMapping) -> bool:
    origin = getattr(m, "mapping_origin", None)
    if origin == MappingOrigin.HUMAN_AUTHORED:
        return True
    if origin == MappingOrigin.AUTO_EXTRACTED:
        return False
    if origin == MappingOrigin.LEGACY_UNKNOWN or origin is None:
        return not _is_auto_extracted_mapping_rationale(m.rationale)
    return False
```
For historical records where origin was unrecorded (`LEGACY_UNKNOWN`), the engine falls back to legacy string prefix heuristics. As records are updated or reviewed through the API, their origin is explicitly promoted.

---

## 4. Security & Tenant Isolation Assurance

- **Cross-Tenant Access Rejection**: `update_clause_mapping_review` requires both `tenant_id` and `clause_id` match. Attempts to review or modify mappings belonging to another tenant fail with `NotFoundError`.
- **RBAC Enforcement**: Mapping approval endpoints continue to require authorized reviewer roles (`compliance_officer`, `risk_lead`, `auditor`).
